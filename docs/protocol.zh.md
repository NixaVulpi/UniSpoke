# 观测到的协议子集

[English](protocol.md) | [Español](protocol.es.md) | 简体中文

[← 返回 README](../README.zh.md)

本文记录 `unispoke` 所实现的 **Leagsoft UniVPN（Huawei SVN）SSL VPN** 协议子集。内容来自厂商实现的分析，以及针对一个已授权网关的互操作测试。未知字段和未经验证的行为均已标注。文中不包含任何凭据、端点或站点特定信息。

## 网关代际

目前观测到两代网关。客户端通过 `FirstConnect` 探测网关，并根据首个响应的 magic 选择代际：

- **Legacy** — HTTPS 登录，16 字节帧，数据复用控制 TLS 连接。
- **V1** — TLS 内的二进制认证，8 字节帧，独立的数据 TLS 通道。

## 帧格式

### V1（8 字节头）

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 4 | magic `c1 92 a4 d6` |
| 4 | 1 | 版本 `01` |
| 5 | 1 | 命令 |
| 6 | 2 | 载荷长度，大端，不含头部 |
| 8 | n | 载荷 |

### Legacy（16 字节头）

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 4 | magic `fe fc ef be` |
| 4 | 4 | magic `c1 92 a4 d6` |
| 8 | 4 | 会话 ID（用户 ID），大端 |
| 12 | 2 | 命令，大端 |
| 14 | 2 | 载荷长度，大端 |
| 16 | n | 载荷 |

Legacy 的一个响应（ACL 响应）使用小端长度字段，其余响应均为大端。读取方必须同时兼容两种字节序。

## Legacy 会话建立

1. HTTPS `GET /netextension/netextensionlogin.html?SelectLanguage=0&UserName=..&Password=..&MacAddress=..&SVN_Seco_AaA=1`
2. 响应是二进制而非 HTTP：magic `f0 f0 f0 f0`，`+4` 处为带符号的结果（负数表示失败），`+44` 处为用户 ID。
3. 新建一条 TLS 连接，发送 ACL（cmd `0x06`，四个零字节）和 REQVIP（cmd `0x03`）。
4. REQVIP 响应为固定布局：`+0` 为 VIP，`+4` 为掩码，`+8` 为地址分配方式，`+20` 为路由类型，`+160` 为三个 DNS 服务器，`+184` 为路由数量，`+188` 起为 12 字节的路由项。
5. 数据使用 cmd `0x02`，载荷为裸 IPv4 包。控制通道保活为 cmd `0x07`，每 10 秒一次。

## V1 会话建立

1. `FirstConnect`（cmd `0x1D`，Legacy 帧格式）：64 字节操作系统信息、256 字节认证域，以及四字节 `00 01 00 00`，共 340 字节。
2. `AUTH`（cmd `0x01`）：256 字节域、16 位认证类型，随后为 TLV——类型 1 用户名、类型 2 密码、类型 3 MAC 字符串。
3. 响应 `+0` 处为结果，`+8` 起为 TLV；类型 3、长度为 32 的是会话令牌。
4. `REQVIP`（cmd `0x03`）携带该令牌。响应基于 TLV：类型 1（长度 5）为 VIP，类型 5/6 为路由，类型 7 为隧道模式，类型 9 为 UDP 端口。
5. 第二条 TLS 连接携带令牌发送 `DATA_CONNECT`（cmd `0x64`）。
6. 数据使用 cmd `0x66`，载荷为八个零字节加裸 IPv4 包。控制通道保活为 cmd `0x06`（令牌 + 已过毫秒数，10 秒）；数据通道保活为 cmd `0x65`（空载荷，15 秒）。

## 重连

厂商客户端会保留已认证会话：

1. 通道失效时设置重连标志；10 秒看门狗启动该流程。
2. 客户端把当前 VIP 保存为基准值，并用相同参数向同一网关建立新的 TLS 连接。
3. 重新发送 REQVIP（若地址分配使用 DHCP，则发送 DHCP）。
4. 新 VIP 必须与基准值一致；否则重连失败，并提示用户重新登录。
5. 成功后，V1 通过 `DATA_CONNECT` 重建数据 TLS 通道；UDP 模式则重建 UDP 链路。

`unispoke` 在两代网关上均遵循这一行为，并在网关拒绝会话复用时回退到完整登录。

## 端点检查边界

网关可以在隧道建立前要求端点合规检查（CEPS）。认证响应中带有端点检查标志；该标志置位时，厂商客户端会先在控制通道上完成检查，再启动隧道。`unispoke` 未实现该检查，因此此类网关无法完成建立。

## 实现者注记

- 隧道 MTU 约为 1300 字节，MSS 取 1200 是安全的。
- 网关会丢弃 40 字节及以下的 IP 包。裸 TCP ACK 恰好是 40 字节，因此纯 ACK 必须携带可选字段
  （例如四个 NOP TCP 选项）才能通过。`unispoke` 的 `internal/packet` 对所有 ≤40 字节的小包做补齐：
  TCP 追加 NOP 选项，UDP/ICMP 追加 IP NOP 选项（不改变传输层载荷）。
- Legacy 数据载荷可能在 IPv4 包前带有两字节前缀。
- V1 数据载荷在 IPv4 包前以八个零字节开头。

### Legacy UDP 数据面（模式 3）

Legacy 网关在会话认证后还接受 UDP 数据面。客户端用 cmd `0x1A` 请求 UDP 端口（回包为
大端 `u16` 端口），用 cmd `0x0D` 请求隧道模式与密钥（请求负载 `00 00 00 04`，回包为大端
`u32` 模式 + 16 字节 AES-128 密钥）。模式 3（`CHIV_UDPS`）的报文布局：

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0 | 8 | `FE FC EF BE C1 92 A4 D6` |
| 8 | 2 | 上行 `02 1C`，下行 `01 1C` |
| 10 | 2 | `00 10`（下行会变化） |
| 12 | 16 | IV：大端 32 位会话号 + 12 字节随机数 |
| 28 | 20 | 明文 IPv4 头 |
| 48 | n | IP 包其余部分的 AES-128-CBC 密文，零填充到 16 字节边界 |

网关单个 UDP 报文上限为 1280 字节，因此内层 MTU 最大 1240。偏移 12 处的 IV 双向都用于
CBC；密钥来自 cmd `0x0D` 回包。接收端解密后用 IPv4 总长字段裁剪。

### 非 TCP 载荷

网关按 IP 协议号**不做过滤**，数据通道中的裸 IPv4 报文可以是任意协议。逆向阶段实测：

| 协议 | 目标 | 结果 |
|---|---|---|
| ICMP echo | 172.22.1.11 | 3/3，type 0 回包 |
| UDP NTP | 192.168.200.3:123 | 3/3，48 字节应答 |
| UDP NetBIOS | 172.22.1.11:137 | 2/2，157 字节 NBSTAT 应答 |
| UDP DNS | 192.168.200.2:53 | 2/2，29 字节应答 |

因此 SOCKS5 `UDP ASSOCIATE` 可以直接建立在数据通道上，无需实现外层 UDP 传输模式。
注意 UDP 载荷需 >12 字节（20 IP + 8 UDP + payload > 40）；更小的报文必须用 IP 选项补齐。

V1 `REQVIP` 中的 `UDPPort`（TLV 9）属于**隧道外层使用 UDP 承载**的快速传输模式，与载荷
UDP 无关；本项目实现了上述 Legacy UDP 数据面（模式 3），并默认仍使用 TLS/TCP 传输。
